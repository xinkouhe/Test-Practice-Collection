# 163 音乐登录链路排查总结

## 本次处理

- `login_163music.py` 已恢复到 git 中的旧脚本基线版本。
- 手动探针脚本 `manual_probe_163music.py` 已删除。
- 手动探针生成的日志、截图已清理。
- 本轮调试过程中新增的旧脚本日志、截图已清理。

## 已确认的事实

- 旧脚本不是完全失效，存在完整跑通的记录。
- 同一套脚本也会随机失败，失败位置不固定。
- 失败时最常见的报错不是 `NoSuchElement`，而是：

```text
HTTPConnectionPool(host='localhost', port=...): Read timed out
```

- 该超时既出现在 Selenium 自动点击流程里，也出现在手动探针读取点击事件时。
- 手动探针曾记录到以下元素在某些轮次中已经可以被程序正常看到：
  - `选择其他登录模式`
  - `密码登录`
  - `手机号输入框`
  - `密码输入框`
  - `登录按钮`

## 现象判断

- 这不是单纯的 selector 错误问题。
- 这也不是单纯的“页面没显示出来”问题。
- 当前更像是多个因素叠加导致的不稳定：
  - 网易云登录弹窗前端链路有时会卡在加载中。
  - 代理状态会影响该弹窗链路表现，但不是唯一因素。
  - `Edge + WebDriver` 本地会话存在随机假死，表现为 `localhost` 读超时。
  - 站点存在风控或反自动化影响的可能，但目前没有单独证据能完全坐实。

## 结论

- 该项目当前可以出现“偶发成功”，但很难保证稳定复现。
- 继续在当前网易云登录链路上硬磕 Selenium，排查成本很高，收益偏低。
- 如果后续仍要继续尝试，建议优先考虑：
  - 换一个更稳定、风控更弱的练习站点。
  - 或者另起 Playwright 最小实验，再评估是否比 Selenium 更稳定。
